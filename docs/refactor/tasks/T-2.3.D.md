# T-2.3.D — Прогресс-события выполнения плана

| Поле | Значение |
| --- | --- |
| Статус | not_started |
| Шаг плана | Фаза 2, шаг 2.3 |
| Репозиторий | aether |
| Зависит от | T-2.3.A |
| Модель | Claude Sonnet 5 |
| Ревью перед мержем | нет |

## Что сделать
Встроить в executor события Downloading / Verifying / Installing / Complete поверх существующей
системы прогресса (`features/events`, `ProgressService`, `ProgressBarId`), не заводя новую.
Проценты считать от числа файлов плана; для крупных файлов использовать
`fetch_bytes_with_progress`.

## Файлы
- `features/instance/app/use_cases/content_provider/install_plan_executor.rs`
- `features/events/` — при необходимости новый тип события
- `apps/frontend/src/shared/api/bindings/` — перегенерация биндингов, если появился новый DTO события

## Как проверить
- `cargo check -p aether-core` + `bun run build` для фронта, если менялись биндинги.
- Ручной сценарий (после T-2.5): в UI видно движение прогресса при установке пака.

## Ловушки
- События испускаются из async-контекста executor-а; не смешивать с прогрессом host-функций.

## Проверка перед мержем (компенсация уровня модели)
Модель — Sonnet, поэтому обязательны:
1. `cargo check` + сборка фронта, если менялись DTO событий.
2. Ручная проверка: прогресс не застревает на 0 и доходит до 100 при установке пака.
