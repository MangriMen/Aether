# T-1.4 — Декларация `api.hostFunctions` в манифесте

| Поле | Значение |
| --- | --- |
| Статус | not_started |
| Шаг плана | Фаза 1, шаг 1.4 (A10) |
| Репозиторий | aether + packwiz + cf |
| Зависит от | T-1.1, T-1.2, T-1.3 (Q5 решён); сюда же перенесён флаг «обрезано» из T-0.5 (F-21) |
| Модель | Opus 5 — формирует контракт плагин↔ядро |
| Ревью перед мержем | да |

## Что сделать
- Добавить в манифест плагина поле `api.hostFunctions: [string]`.
- При включении плагина проверять, что все запрошенные функции существуют в реестре host-функций;
  неизвестная функция → отказ с внятной ошибкой.
- Регистрировать плагину **только** запрошенные функции (сужение прав), если это не ломает
  загрузку (Extism требует, чтобы импорты модуля были удовлетворены — проверить поведение).
- Отразить поле в `aether-core-plugin-api` (DTO + JSON Schema) и в `xtask` **каждого** плагина
  (схема манифеста там продублирована — F-7).

### Дополнение из T-0.5 (2026-09-22): флаг «обрезано» в `OutputDto` (F-21)
T-0.5 обрезает stdout/stderr `run_command` по 1 MiB на поток, но **флаг обрезки передать не смог**:
`extism-convert` кодирует DTO через `rmp_serde::to_vec` (компактная форма — массив фиксированной
длины), поэтому четвёртое поле в `OutputDto` даёт у старого плагина `Err(LengthMismatch(3))`, а не
игнорируется. Сейчас факт обрезки доносится маркером `\n[aether: output truncated]\n`
в конце потока и `log::warn!` в ядре.

Здесь нужно:
- добавить в `OutputDto` поле `truncated: bool` (или `stdout_truncated`/`stderr_truncated`);
- убрать маркер из `read_capped` в
  `features/plugins/infra/extism/host_functions/features/core.rs` — он был временной заменой поля;
- выкатить по порядку Q5 (ядро → тег `aether-core-plugin-api` → пересборка packwiz), иначе
  `run_command` у уже установленного плагина перестанет декодировать ответ.

Это же ограничение действует для **любого** расширения любого DTO плагинного ABI, не только
`OutputDto`: молча добавить поле нельзя нигде.

### Решение по Q5 (2026-09-20)
- Канонический источник `aether-core-plugin-api` — **`MangriMen/aether-core`**; зависимость
  в packwiz-плагине переводится на него и **пинится на тег/коммит**, не на ветку.
- Порядок выката: ядро → тег `aether-core-plugin-api` → плагины.
- Скелет `curseforge-plugin` в этом проходе не трогаем (Q3): его `xtask` и зависимость
  приводятся в порядок в T-2.4.2.A при возобновлении работы над CF.

## Как проверить
- `cargo check` в трёх репозиториях.
- Тест: манифест с несуществующей host-функцией не включается.
- Ручной сценарий: пересобрать packwiz через `xtask`, установить, включить — работает.

## Ловушки
- Ломающее изменение схемы манифеста: старый плагин без поля должен грузиться (дефолт — пустой
  список = «объявленных нет», выбрать: разрешать все или ничего — зафиксировать в карточке).
- Порядок выката (Q5): ядро → релиз `aether-core-plugin-api` → плагины.
- DTO плагинного ABI кодируются msgpack-массивом фиксированной длины, а не map: добавление поля —
  ломающее изменение для уже собранных плагинов, «совместимо по умолчанию» здесь не работает (F-21).
