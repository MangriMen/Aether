# T-3.4 — Убрать `block_in_place` из host-функций

| Поле | Значение |
| --- | --- |
| Статус | not_started |
| Шаг плана | Фаза 3, шаг 3.4 (A2, A14) |
| Репозиторий | aether |
| Зависит от | — |
| Модель | Opus 5 — многопоточность, поведение Extism из исходников |
| Ревью перед мержем | да |

## Что сделать
- Вынести синхронный вызов плагина в `spawn_blocking` на уровне
  `PluginContentProviderProxy` (и прочих прокси), чтобы не блокировать tokio-воркер.
- Не держать `tokio::sync::Mutex` плагина на всё время вызова (A14) — пересмотреть владение
  `Arc<Mutex<dyn PluginInstance>>` (например, блокировка внутри blocking-задачи).
- Убрать `execute_async` из host-функций; учесть, что он используется **всеми** host-функциями
  (F-11), а не только контент-провайдером.

## Файлы
- `shared/execute_async/infra/mod.rs`
- `features/plugins/infra/plugin_content_provider_proxy.rs`,
  `plugin_importer_proxy.rs`, `plugin_updater_proxy.rs`
- `features/plugins/infra/extism/host_functions/features/{core.rs,java.rs,instance.rs}`

## Как проверить
- `cargo test -p aether-core`.
- Нагрузочный ручной сценарий: установка пака при одновременном запуске другой операции
  (поиск контента) — UI не залипает, дедлока нет.

## Ловушки
- Host-функции вызываются **изнутри** синхронного `plugin.call`, который сам уже будет
  в `spawn_blocking` — попытка сделать из них async вызов в тот же рантайм даёт риск
  блокировки; менять аккуратно и по одной функции.
- Реентерабельность Extism запрещена: из host-функции нельзя вызвать тот же плагин.
