## Что сделать
Заменить `archive.extract(&temp_dir)` на ручной обход записей с `entry.enclosed_name()`:
- запись без `enclosed_name()` → ошибка `PluginError::FileExtractionFailed`;
- создавать директории явно, писать файлы через `std::io::copy`;
- заодно ограничить суммарный распакованный размер и число записей (защита от zip-бомбы),
  константы вынести в `ZipPluginExtractorConstants`.

## Файлы
- `features/plugins/infra/zip_plugin_extractor/extractor.rs`
- `features/plugins/infra/zip_plugin_extractor/constants.rs` (или где лежит структура констант)

## Как проверить
- `cargo test -p aether-core` + новый тест: zip с записью `../evil.txt` → ошибка, файл вне
  `temp_dir` не создан.
- Ручной сценарий: обычный плагин-архив по-прежнему устанавливается.

## Ловушки
- `enclosed_name()` возвращает `Option`, а не `Result`.
- На Windows абсолютные пути с буквой диска тоже отсекаются `enclosed_name()` — это желаемое.

## Проверка перед мержем (компенсация уровня модели)
Модель — Flash, поэтому обязательны:
1. Тест на архив с записью `../evil.txt` — файл вне `temp_dir` не создан.
2. Тест на архив с абсолютным путём (в том числе с буквой диска Windows).
3. Ручная проверка: обычный плагин-архив по-прежнему устанавливается.
