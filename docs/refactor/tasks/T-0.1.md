## Что сделать
Задать плагинам ресурсные лимиты при загрузке:
- `Manifest::with_memory_max(pages)` — **метод `Manifest`**, принимает страницы по 64 KiB;
- `Manifest::with_timeout(Duration)` — **метод `Manifest`**;
- `PluginBuilder::with_fuel_limit(u64)` — **метод `PluginBuilder`**.

Значения: из `LoadConfig::Extism { memory_limit }`, если задано, иначе — константы-дефолты хоста
(вынести в один модуль констант рядом с `ExtismPluginLoader`).

### Решение по Q8 (2026-09-20)
- `memoryLimit` в манифесте остаётся **в байтах**; конвертация в страницы по 64 KiB
  (округление **вверх**) делается в загрузчике ядра.
- Дефолт при отсутствии значения — **256 MiB**.
- Дополнительно починить генератор манифеста в `xtask` packwiz-плагина: сейчас он всегда
  пишет `memoryLimit: null` (F-4). В `curseforge-plugin` — при возобновлении работы над CF.

## Как проверить
- `cargo check -p aether-core` и `cargo clippy -p aether-core -- -D warnings`.
- Юнит-тест: манифест с `memory_limit` → у собранного `Manifest` выставлены `memory.max_pages`
  и `timeout_ms` (проверять через сериализацию `Manifest` в JSON).
- Ручной сценарий: включить packwiz-плагин, импортировать пак — плагин грузится и работает.

## Ловушки
- `with_memory_max` на `PluginBuilder` не существует — это ошибка исходного аудита.
- Поле манифеста документировано в байтах, API принимает страницы (F-4). Конвертация — вверх.
- Слишком маленький `fuel_limit` убьёт долгие вызовы (пока packwiz ходит через `run_command`
  и jar, реальная работа идёт вне WASM, но резолв пака после Фазы 2 будет длинным).

## Проверка перед мержем (компенсация уровня модели)
Модель — Flash, поэтому ревьюер (или Opus-агент) обязан перепроверить руками:
1. `with_memory_max`/`with_timeout` вызваны на `Manifest`, `with_fuel_limit` — на `PluginBuilder`.
2. Конвертация байт → страницы округляет **вверх** и не переполняет `u32`.
3. Дефолт 256 MiB применяется, когда в манифесте `memoryLimit` отсутствует.
4. packwiz-плагин после правки включается и импортирует пак (лимиты не режут jar-путь).
