## Что сделать
Собственная host-функция `http_get(request) -> HttpResponse`:
- отдельный `reqwest::Client` с `redirect::Policy::none()` (общий клиент приложения следует
  редиректам — F-9);
- проверка хоста **в хосте** по `allowed_hosts` плагина (манифест + настройки), а не только
  внутри Extism;
- запрет приватных/loopback/link-local адресов (в т.ч. `169.254.169.254`) — резолвить имя
  и проверять все полученные IP;
- лимит размера ответа и таймаут;
- DTO запроса/ответа — в `aether-core-plugin-api` (`v0`), рядом с существующими DTO.

Встроенный `http_request` Extism остаётся как fallback — задокументировать риск редиректов
в README плагинного API.

## Файлы

- `packages/core/aether-core-plugin-api/src/v0/dto/` — `HttpRequestDto`/`HttpResponseDto`
- `features/plugins/infra/extism/host_functions/plugin_context.rs` — нужен доступ к
  `allowed_hosts` плагина (сейчас контекст знает только `id` и контейнер)

## Как проверить
- `cargo test -p aether-core`: unit-тесты матчинга `allowed_hosts` (включая wildcard-формы,
  которые поддерживает Extism) и отсечения приватных IP.
- Интеграционный тест на локальном http-сервере: ответ 302 на другой хост → ошибка, а не переход.
- Ручной сценарий: плагин, вызывающий `http_get` к разрешённому хосту, получает тело ответ.

## Ловушки
- `PluginContext` сейчас не хранит манифест — нужно пробросить allowed_hosts при создании
  контекста в `get_host_functions` (подпись меняется, затрагивает все host-функции).
- DNS rebinding: проверять IP **после** резолва и использовать тот же резолв для запроса
  (или хотя бы задокументировать остаточный риск).
- Запрос идёт из синхронного контекста Extism — пока через `execute_async`; не чинить это здесь,
  это задача T-3.4.

## Как это сделано (2026-09-21)
- `HttpRequestDto` / `HttpResponseDto` — `aether-core-plugin-api/src/v0/dto/http.rs`.
- Host-функция и вся логика — `.../extism/host_functions/features/http.rs`.
  Порядок проверок: схема (`http`/`https`) → `allowed_hosts` **в хосте** (та же glob-семантика,
  что у Extism, — зеркалит `extism/src/pdk.rs`) → фильтр заголовков → резолв имени и запрет
  непубличных адресов (loopback, private, link-local вкл. `169.254.169.254`, CGNAT, multicast,
  documentation, reserved; IPv4 и IPv6, включая `::ffff:a.b.c.d`) → пин запроса на уже
  проверенные адреса (`resolve_to_addrs`, закрывает DNS rebinding) → запрос отдельным
  `reqwest::Client` с `redirect::Policy::none()` → 3xx = ошибка → лимит тела 16 MiB,
  таймаут 30 с / connect 10 с.
- `PluginContext` получил поле `allowed_hosts`; `get_host_functions` — третий параметр.
  Загрузчик резолвит список один раз и отдаёт его и в Extism-манифест, и в host-функции,
  так что оба пути видят ровно один и тот же allowlist.
- Риск редиректов встроенного `http_request` задокументирован в новом
  `packages/core/aether-core-plugin-api/README.md`.
