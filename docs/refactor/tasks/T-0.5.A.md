## Проблема
Allowlist `run_command`, принятый по Q7 и реализованный в T-0.5, разрешает запуск только если
канонизированный путь программы лежит внутри `location_info.java_dir()`. Но `get_java` отдаёт
то, что лежит в таблице `java_versions`, а туда `DiscoverJavaUseCase` кладёт **и системные
установки** (`features/java/infra/discovery_paths.rs`). Получается расхождение: ядро само выдало
плагину путь, а потом само же отказалось его запускать.

Симптом: у пользователя в БД для нужной мажорной версии — системная Java (например,
`C:\Program Files\Java\...`), packwiz получает её из `get_java(8)` и падает на `run_command`
с `AccessViolation`. Обновление пака ломается.

На машине владельца на 2026-09-21 риска нет: в `java_versions` только пути внутри `cache/java`,
Java 8 не зарегистрирована вообще, поэтому packwiz уходит в `install_java(8)` → `java_dir()`.
Это везение конкретной установки, а не свойство кода.

## Что сделано (вариант (d) по Q10)
- `plugin_utils::java_bin_dirs` — строит список разрешённых директорий из путей `java_versions`:
  канонизация, файл → родительский `bin`, нерезолвящиеся записи отбрасываются.
- `resolve_allowed_program` сравнивает родителя канонического `program` с этим списком;
  сравнение с `location_info.java_dir()` убрано.
- `plugin_command_to_host` принимает `allowed_program_dirs: &[PathBuf]`.
- `handle_run_command` читает список через `container.list_java_use_case()` на каждый вызов —
  удалённая из БД Java должна перестать быть разрешённой сразу.

Миграция БД и флаг в модели `Java` **не понадобились** — в этом главный плюс (d) перед (b).

## Файлы
- `features/plugins/infra/plugin_utils.rs` (`java_bin_dirs`, `resolve_allowed_program`,
  `plugin_command_to_host`)
- `features/plugins/infra/extism/host_functions/features/core.rs` (`handle_run_command`)

- Ручной сценарий (не выполнен, нужен GUI): обновление packwiz-пака на инстансе,
  где активна системная Java — тот же блокер, что у T-0.5.

## Ловушки
- Сверка идёт с `bin`-директорией, а не с точным файлом: иначе `java.exe` рядом с
  зарегистрированным `javaw.exe` перестал бы запускаться. Следствие: разрешены и соседние
  утилиты JRE (`keytool` и пр.). Приемлемо: по F-23 граница здесь всё равно мягкая.
- Правило стало **строже** прежнего по Q7: лежать где-то внутри `java_dir()` больше
  недостаточно. Если когда-нибудь плагину понадобится запускать не-Java из каталога ядра,
  это будет отказ с `AccessViolation` и понятным путём в ошибке.

## Осталось
- Ручной сценарий не выполнен (нет GUI) — проверяется вместе с ручным сценарием T-0.5.
