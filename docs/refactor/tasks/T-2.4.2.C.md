## Что сделать
- `resolve_file(content_id, version, game_version, loader)` — главный метод: именно его через
  ядро вызывает packwiz для записей `ProviderRef` (projectID/fileID);
- `resolve_install_plan` — для CF-модпаков: разбор `manifest.json` из zip-модпака, файлы →
  `ContentSource::ProviderRef` (сам CF), `overrides/` → `OverrideSource::Archive`;
- `resolve_pack_metadata` — лёгкий preview без резолва файлов.

## Файлы
- `curseforge_plugin/src/features/curseforge_api/*`
- `curseforge_plugin/src/lib.rs`, `capabilities.json`

## Как проверить
- Ручной сценарий 1: установка CF-модпака в новый инстанс.
- Ручной сценарий 2 (после T-2.4.3.B): packwiz-пак с CF-записями устанавливается, файлы
  скачиваются — то есть `ProviderRef` резолвится ядром через этот плагин.

## Ловушки
- Файлы с `allowFileDistribution: false` не имеют прямого `downloadUrl` (решение Q3).
- Идентификатор контента для `ProviderRef` должен быть однозначным (`projectId` и `fileId`) —
  зафиксировать формат строки `content_id`/`version` и записать его здесь, потому что тот же
  формат обязан генерировать packwiz в T-2.4.3.B.
