## Отложенное из Q12 (c) — рассмотреть при выполнении
Владелец закрыл **Q12** вариантом (a): концепция `PackManager` с ветки
`fix/fix-instance-intall-stage-during-modpack-installing` отвергнута, `InstallPlan` остаётся.
Но один элемент той ветки отложен сюда **к рассмотрению, а не к обязательному внедрению**:

> явный дешёвый вызов `check_updates` с типом-ответом `UpdateStatus`
> (`NoUpdates` / `UpdatesAvailable { current_version, latest_version }` / `Unsupported`)
> — см. `git show fix/fix-instance-intall-stage-during-modpack-installing:packages/core/aether-core/src/features/instance/domain/model/update_status.rs`

Вопрос к этой задаче: покрывает ли `resolve_pack_metadata` + сравнение потребность «есть ли
обновление», или отдельный `check_updates` читается яснее и дешевле. **Оба ответа допустимы.**
Если решишь не добавлять — зафиксируй причину в «Журнале» карточки, чтобы вопрос не всплывал
третий раз. Если добавишь — он обязан укладываться в требование Q3 (расширяемость под CF)
наравне с остальными методами трейта.

## Что сделать
Добавить в трейт `resolve_file`, `resolve_install_plan`, `resolve_pack_metadata`
с дефолтными реализациями, возвращающими `InstanceError::UnsupportedOperation`, чтобы
существующие провайдеры продолжали компилироваться. `install_atomic`/`install_modpack`
пока остаются (удаляются в T-3.1). Метод `metadata()` сохранить (F-10).

### Требование расширяемости под CurseForge (Q3, 2026-09-20)
`resolve_file` и `resolve_install_plan` входят в трейт **сейчас**, хотя единственным
мигрированным провайдером в этом проходе будет Modrinth. Критерий приёмки: добавление
CurseForge-плагина позже не должно требовать изменения сигнатур трейта.
При ревью проверить, что параметры `resolve_file` достаточны для CF-семантики
(project id + file id + game version + loader), даже если сейчас их использует только Modrinth.
