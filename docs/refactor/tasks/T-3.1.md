# T-3.1 — Удалить `install_atomic` / `install_modpack`

> **ОТЛОЖЕНО.** Удаление старых методов возможно только после миграции **всех** провайдеров,
> а packwiz (Q1) и CurseForge (Q3) отложены. До тех пор `install_atomic`/`install_modpack`
> остаются в трейте рядом с новыми `resolve_*`.

| Поле | Значение |
| --- | --- |
| Статус | **ОТЛОЖЕНО — требует мигрированных packwiz и CF** |
| Шаг плана | Фаза 3, шаг 3.1 |
| Репозиторий | aether + aether-core-plugin-api |
| Зависит от | T-2.4.1, T-2.4.2.C, T-2.4.3.D |
| Модель | Claude Sonnet 5 (на будущее — неактуально в текущем проходе) |
| Ревью перед мержем | нет |

## Что сделать
Убрать из трейта `ContentProvider`, из `ProviderHandlers`/DTO, из прокси и из Modrinth
методы `install_atomic`/`install_modpack` и связанные типы (`AtomicInstallParams`,
`ModpackInstallParams`, `DownloadedContent`), если они больше нигде не нужны.

## Файлы
- `features/instance/app/ports/content_provider.rs`
- `features/instance/domain/model/{content.rs,downloaded_content.rs}`
- `features/plugins/infra/plugin_content_provider_proxy.rs`
- `aether-core-plugin-api/src/v0/dto/*`
- Modrinth-провайдер

## Как проверить
- `cargo check` воркспейса, `cargo test -p aether-core`, clippy без предупреждений.
- Ручной сценарий: установка мода и модпака по-прежнему работает.

## Ловушки
- Не удалять раньше, чем **все три** провайдера реально работают на новом контракте —
  это явное условие плана.
