## Что сделать
Две host-функции:
- `write_instance_file(instance_id, relative_path, bytes)` — единственный способ записи в инстанс;
- `read_instance_file(instance_id, relative_path) -> bytes`.

Требования: `relative_path` всегда относительный, без `..`, без абсолютных префиксов и без
symlink-выхода за корень инстанса (канонизировать и сравнить с корнем — как уже делает
`plugin_path_to_host`); лимит размера; проверка, что инстанс существует.

## Файлы
- `features/plugins/infra/extism/host_functions/features/instance.rs`
- `features/plugins/infra/extism/host_functions/get_host_functions.rs`
- `aether-core-plugin-api/src/v0/dto/instance/` — DTO параметров
- переиспользовать `InstanceFileService` / `ContentFileService` из `features/instance/app/ports`

## Как проверить
- `cargo test -p aether-core`: `../` в пути, абсолютный путь, symlink наружу — все отклоняются.
- Ручной сценарий: временный тестовый вызов из packwiz (или unit-тест на хост-функции),
  файл появляется внутри директории инстанса.

## Ловушки
- Пути от плагина приходят в WASI-форме (`/instances/...`, `/mnt/d/...` на Windows) —
  для этих функций принимать **только** `instance_id` + относительный путь, не WASI-путь.
- Запись должна идти через тот же слой, что и остальная запись в инстанс, иначе состояние
  `PackStorage` разъедется с диском.
