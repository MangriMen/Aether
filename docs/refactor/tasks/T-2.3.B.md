# T-2.3.B — Диффинг install/update против `PackStorage`

| Поле | Значение |
| --- | --- |
| Статус | not_started |
| Шаг плана | Фаза 2, шаг 2.3 |
| Репозиторий | aether |
| Зависит от | T-2.3.A |
| Модель | Opus 5 — здесь легко потерять пользовательские файлы |
| Ревью перед мержем | да |

## Что сделать
`diff_against_installed(instance_id, resolved_files) -> (to_download, to_remove)`:
- сравнение по относительному пути + хешу с записями `PackStorage` (`PackFile`);
- файл с совпадающим хешем не перекачивается;
- файл, которого нет в новом плане, но есть в `PackStorage` **и** принадлежит этому паку —
  в `to_remove`; файлы, добавленные пользователем вручную (нет в `PackStorage`), не трогать;
- отключённые пользователем файлы (`disabled`) — решить и задокументировать поведение
  в этой карточке (сохранять состояние «отключён» при обновлении).

## Файлы
- `features/instance/app/use_cases/content_provider/install_plan_executor.rs`
- `features/instance/app/ports/pack_storage.rs` — при необходимости расширить API выборки
- `features/instance/infra/sqlite/sqlite_pack_storage.rs`

## Как проверить
- `cargo test -p aether-core`: unit-тесты диффа на наборах (новый файл / изменённый хеш /
  исчезнувший файл / чужой файл / отключённый файл).
- Ручной сценарий (после T-2.5): установить пак, вручную добавить мод, обновить пак —
  вручную добавленный мод остаётся.

## Ловушки
- Соответствие терминов (F-5): план говорит `ContentFile` — в коде это `PackFile` и методы
  `update_pack_file`, `update_pack_file_many`, `remove_pack_file`, `find_by_provider_id`.
- Отключённые моды в инстансе лежат с изменённым именем файла (`.disabled`) — сравнение путей
  должно это учитывать, иначе обновление продублирует мод.
