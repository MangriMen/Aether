# T-3.5 — Структурированные ошибки на границе WASM

| Поле | Значение |
| --- | --- |
| Статус | not_started |
| Шаг плана | Фаза 3, шаг 3.5 |
| Репозиторий | aether |
| Зависит от | T-3.3 |
| Модель | Opus 5 — малодокументированное поведение Extism |
| Ревью перед мержем | да |

## Что сделать
Различать на границе вызова плагина: `Trap`, `Timeout`, `OutOfFuel`, `OutOfMemory`,
`PluginError` (ошибка, которую вернул сам плагин), `NonZeroExit` — через
`call_get_error_code` и анализ текста ошибки. Ввести соответствующие варианты ошибок
и внятные сообщения для UI.

## Файлы
- `features/plugins/infra/extism/models/extism_plugin_instance.rs` (`call_bytes`)
- `features/plugins/domain/models/plugin_error.rs`
- `features/plugins/infra/extism/mappers/result.rs`

## Как проверить
- `cargo test -p aether-core` + тесты на тестовом wasm-плагине, который умеет: зациклиться
  (timeout/fuel), аллоцировать много памяти, вернуть ошибку, паниковать.
- Ручной сценарий: плагин с бесконечным циклом даёт понятное сообщение «превышен лимит»,
  а не «function call failed».

## Ловушки
- Классификация по подстрокам текста ошибки хрупкая — зафиксировать её в одном месте
  и покрыть тестами, чтобы обновление Extism ломало тест, а не прод.
- Зависит от того, что лимиты из T-0.1 реально выставлены, иначе часть веток недостижима.
