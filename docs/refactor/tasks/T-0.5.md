## Что сделать
- Allowlist программ: разрешать только исполняемые файлы, путь которых хост сам и выдал
  (host-managed Java из `get_java`/`install_java`). Сравнение — по канонизированному пути.
- Убрать fallback на сырую строку в `plugin_command_to_host`: если `program` не резолвится
  в разрешённый путь — ошибка `PluginError::AccessViolation`, а не запуск как есть (F-13).
- Таймаут выполнения и лимит размера собранного stdout/stderr (обрезать + флаг «обрезано»).
- Изоляция окружения: `Command::env_clear()` + явный минимальный набор переменных;
  `current_dir` обязателен и обязан лежать внутри смонтированных плагину директорий.

### Решение по Q7 (2026-09-20)
Allowlist на этом проходе: запуск разрешён, **только если канонизированный путь программы
резолвится внутрь директории Java, управляемой ядром** (та, что выдают `get_java` /
`install_java`). Совпадение по имени файла (`java`, `java.exe`) основанием не является.
packwiz остаётся на jar-пути (Q1), поэтому этот путь обязан продолжать работать.

## Файлы
- `features/plugins/infra/extism/host_functions/features/core.rs` (`handle_run_command`)
- `features/plugins/infra/plugin_utils.rs` (`plugin_command_to_host`)
- `shared/serializable_command/domain/*` (`to_tokio_command`, возможно поле `env`)

## Как проверить
- `cargo test -p aether-core` + тесты: произвольный `program` (`cmd.exe`, `/bin/sh`) отклоняется;
  путь к host-managed Java проходит; вывод длиннее лимита обрезается.
- Ручной сценарий (обязателен): обновление packwiz-пака в инстансе всё ещё работает
  (пока jar-путь не удалён задачей T-2.4.3.D).

## Ловушки
- packwiz передаёт `program` как путь к Java, полученный из host-функции, а аргументы — в виде
  `#/cache/...` и `#/instances/...`; резолв `#`-путей ломать нельзя.
- На Windows `env_clear()` без `SystemRoot`/`PATH` ломает запуск JVM — оставить минимальный набор.
