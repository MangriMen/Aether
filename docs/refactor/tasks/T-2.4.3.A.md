## Что сделать
Дополнить существующий разбор `pack.toml` (он уже нативный, `toml` в зависимостях) разбором
цепочки индекса:
- `pack.toml` → `index.file` + `index.hash-format`/`hash`;
- `index.toml` → список `files[]` с `file`, `hash`, `metafile`;
- метафайлы `*.pw.toml` → `name`, `filename`, `side`, `download { url, hash, hash-format, mode }`,
  `update { curseforge { project-id, file-id }, modrinth { mod-id, version } }`.
Проверка хешей индекса и метафайлов. Пока — только модель и парсер, без `resolve_*`.

## Файлы

- `packwiz/src/features/packwiz/app/get_pack_from_path_or_url.rs`
- новые модули для `index.toml` и метафайлов

## Как проверить
- `cargo test -p packwiz` — юнит-тесты парсера на фикстурах реального пака (и с CF-записями,
  и с прямыми `download.url`).
- `cargo build` / `xtask build` — плагин собирается под wasm.

## Ловушки
- `hash-format` у packwiz — чаще `sha256`, иногда `sha1`/`md5`; в плане `FileHash` их нет (F-6, Q6).
- `mode = "metadata:curseforge"` означает, что прямого URL нет — такие записи пойдут
  в `ProviderRef` (T-2.4.3.B).
- Загрузка по URL пока идёт через встроенный `http_request` — на host-функцию `http_get`
  переводить в T-2.4.3.D, не здесь.
