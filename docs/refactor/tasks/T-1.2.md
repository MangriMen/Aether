# T-1.2 — Host-функция `download_to_cache`

| Поле | Значение |
| --- | --- |
| Статус | not_started |
| Шаг плана | Фаза 1, шаг 1.2 |
| Репозиторий | aether |

| Модель | Opus 5 — единая точка скачивания + верификация хеша |
| Ревью перед мержем | да |

## Что сделать
`download_to_cache(url, hash) -> CachedFile`: скачивание через `RequestClient` (ретраи и
семафор уже есть), запись в `plugin_cache_dir` плагина, верификация хеша, возврат пути
в плагинном пространстве (`/cache/...`). Хост-проверки URL — те же, что в T-0.6.

Расширить проверку хеша в `RequestClient`: сейчас поддерживается только sha1
(`Request::with_sha1`) — нужен обобщённый `FileHash` (см. Q6, T-2.1.A).

### Решение по Q6 (2026-09-20)
`FileHash { Sha1, Sha256, Sha512 }`, в ядро добавляется крейт `sha2`. Md5 не добавляем.
Верификация в `RequestClient` обобщается с `with_sha1` на `FileHash`.

## Файлы
- `features/plugins/infra/extism/host_functions/features/` — новый модуль или `http.rs`
- `shared/request_client/domain/models/request.rs`, `shared/request_client/infra/reqwest.rs`
- `shared/hash/infra/mod.rs`
- `aether-core-plugin-api/src/v0/dto/` — `CachedFileDto`

## Как проверить
- `cargo test -p aether-core`: несовпадение хеша → ошибка и файл не остаётся в кеше.
- Ручной сценарий: плагин скачивает файл, путь возвращается как `/cache/<...>` и читается
  плагином через WASI.

## Ловушки
- Имя файла в кеше не должно приходить от плагина напрямую (path traversal) — генерировать
  из хеша/URL, а не из подсказки плагина.
- Частично скачанный файл не должен оставаться под финальным именем: писать во временный,
  затем `rename`.
